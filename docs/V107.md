# V.107 — Catalogo colori Bambu e backup automatici

30 ottobre 2026. Base V.106; modello del registro e chiave localStorage invariati.

## Catalogo verificato

Il file ufficiale [filaments_color_codes.json di Bambu Studio](https://github.com/bambulab/BambuStudio/blob/804d93bb5de142c48c0dabedba87736ea9553206/resources/profiles/BBL/filament/filaments_color_codes.json) contiene 318 codici univoci in 46 famiglie. La copia fattuale inclusa nell'app conserva nome italiano/inglese e campioni RGBA; `catalogo-bambu-fonte.json` registra commit, URL, impronta SHA-256 e data di acquisizione. `catalogo-colori-bambu.csv` consente la consultazione esterna.

Esempi di correzioni rispetto alle vecchie mappe: 10102 è Argento, 10201 Beige, 10501 Verde bambù e 10601 Blu. Le mappe numeriche non verificate sono state sostituite dal catalogo unico; un codice assente non riceve un colore inventato. I colori multicolore usano le tinte della fonte, quelli trasparenti un fondo a scacchi. Il monitor, la finitura e la luce impediscono di garantire l'identità con il campione stampato.

La visualizzazione completa i nomi usando il codice nella variante o nel campo separato del record. Il colore della singola bobina prevale sul codice generale quando diverso. Le etichette personali vengono mantenute; l'arricchimento riguarda il rendering e la ricerca, non una riscrittura dell'inventario o del backup.

## Backup su cartella

L'utente seleziona e autorizza una cartella con File System Access. Il registro continua a salvare nel browser. I JSON periodici riusano lo stesso snapshot validato dell'esportazione manuale: nessuna seconda copia del modello dei dati viene mantenuta.

La cartella viene ricordata tramite IndexedDB, perché un handle non è serializzabile nel JSON. Lo stato della scrittura è visibile nel pannello di backup; se i permessi non restano concessi va premuto Riattiva backup. La prima copia è immediata, le successive ogni cinque minuti quando cambiano i dati. Al ritorno nella scheda viene tentata un'ulteriore copia. Salva JSON ora forza la scrittura.

Ogni esecuzione salva una copia datata e poi aggiorna `registro_filamenti_ultimo_backup.json`. Le scritture si completano con `close()` e un errore tenta `abort()`; le vecchie copie non sono eliminate. Non vengono avviate scritture simultanee. Un registro non valido, bloccato da un conflitto o non salvabile non viene presentato come un backup riuscito.

I timer possono essere rallentati nelle schede sospese. Non esiste la garanzia di completare una scrittura asincrona quando il browser viene terminato: il salvataggio locale e i JSON periodici sono due protezioni distinte. Le modifiche nei moduli devono essere confermate prima di essere parte del registro.

Riferimento API: [documentazione Chrome](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access).

## Verifica

Superati 68 test unitari e 31 scenari Chromium, con contesti temporanei. Coperti codici corretti, varianti individuali, ricerca, nomi personali, codici ignoti, multicolore, scritture valide, timer di cinque minuti, riapertura con IndexedDB, disattivazione, permesso negato, quota, disco pieno, concorrenza e retrocompatibilità.

La prova delle API file nel browser usa la cartella privata di un profilo temporaneo, senza accesso al registro o alle cartelle personali. L'autorizzazione alla cartella Windows deve essere concessa dall'utente nell'app.
